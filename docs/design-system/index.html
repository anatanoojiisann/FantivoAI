创作：单屏完成，异步交付

主操作只在必填项有效时启用；提交后立即进入可恢复的任务状态。

  1. 选择模式文本 / 图片
  2. 完成输入素材 + Prompt
  3. 确认参数比例 · 时长 · 成本
  4. 提交生成幂等 requestId
  5. 进入作品显示排队与进度
成功标准用户在首屏内看见输入、参数、成本和主操作；失败任务说明退款或重试路径。

内容发现：先预览，再承诺

内容卡只负责打开详情；是否可创作、需要几张图，在详情层明确判断。

  1. 浏览 Feed横向内容轨道
  2. 打开详情媒体 + Prompt + 参数
  3. 当前可创作？能力检查
  4. 是：带入创作锁定所需模式
  5. 否：保留预览禁用并解释原因
成功标准禁用态必须有原因；从模板进入创作后保留来源、Prompt 与所需素材数量。

任务：状态先行，动作随状态出现

卡片用于扫描；全屏详情承载播放器、发布、分享、再次创作与完整元数据。

  1. 筛选任务全部 / 进行中 / 完成 / 失败
  2. 扫描状态图标 + 文案 + 进度
  3. 打开详情覆盖层保留列表位置
  4. 执行后续动作发布 / 分享 / 再创作
  5. 返回列表筛选与滚动不丢失
成功标准进行中才显示取消；完成后才显示输出动作；失败显示原因、退款状态和恢复动作。

钱包：法律同意解锁支付

余额、订阅与一次性积分是同一页面的三个层级，Telegram invoice 是唯一支付出口。

  1. 查看余额当前可用 credits
  2. 确认条款未同意时禁用购买
  3. 选择商品订阅或一次购买
  4. Telegram 支付打开官方 invoice
  5. 服务端确认到账后刷新余额
成功标准客户端 paid 不直接加款；等待 successful_payment 后刷新，避免重复入账。
